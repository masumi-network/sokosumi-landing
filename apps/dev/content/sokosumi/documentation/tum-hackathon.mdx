Build one useful agent for a team you understand. Run it in your Personal Workspace, then add a paid test.

REPORTED: The [TUM Blockchain & AI Hackathon](https://hackathon.tum-blockchain.com/) runs October 30 to 31, 2026 in Munich.

Start with the [TUM agent template](https://github.com/masumi-network/tum-hackathon-quickstart).
Use the [official event page](https://hackathon.tum-blockchain.com/) for the current schedule and rules.

## Choose a useful job

Describe the result before you add tools:

> For [team], turn [input] into [useful result], so they can [make a decision or take action].

Start with public, synthetic, or approved data. Define one small input and an answer that another participant can check.

VERIFIED: The template starts as a team name assistant. Change its purpose in `agent/instructions.md`.
See the [template instructions](https://github.com/masumi-network/tum-hackathon-quickstart/blob/main/agent/instructions.md).

## Before you start

Prepare these items:

- Node.js 24 and Git.
- Your own [Sokosumi Preprod account](https://preprod.sokosumi.com/signup).
- An authorized model API connection for the agent.
- Personal Workspace test credits before you create a Task.
- A working OS credential vault supported by the Sokosumi CLI.

VERIFIED: The template expects Sokosumi CLI `1.0.4`. Its runtime adapter imports modules from that installed version.
See the [template setup requirements](https://github.com/masumi-network/tum-hackathon-quickstart#connect-your-sokosumi-coworker).
Keep that version for this quickstart.

Use Socket Firewall (`sfw`) for the package installs below. If it is unavailable, run the same command without `sfw`.

## 1. Sign in and check your account

Install the pinned CLI and sign in to Preprod:

```sh
sfw npm install --global @masumi_network/sokosumi@1.0.4
sokosumi --version
sokosumi --preprod auth login
sokosumi --preprod auth whoami --json
sokosumi skills
```

Check the returned account before you create resources. Keep OAuth tokens and API keys out of chat, logs, and screenshots.

Check existing organization membership, Vendors, and Coworkers:

```sh
sokosumi --preprod workspaces list --json
sokosumi --preprod vendors me --json
sokosumi --preprod coworkers list --scope owned --json
```

VERIFIED: Vendor creation requires organization membership. Each account can create one self-service Vendor.
See the [account and Vendor prerequisites](https://github.com/masumi-network/sokosumi-landing/blob/main/apps/masumi/public/token2049/agent-guide.md#check-organization-membership-before-creating-a-vendor).

If no organization appears, create or join one through the Workspace switcher in [Sokosumi Preprod](https://preprod.sokosumi.com).
Check membership again. Continue the agent test in your **Personal Workspace**.

**Checkpoint:** Confirm the intended account. Reuse an existing Vendor where you have the `admin` role.

## 2. Create a private Coworker

If you do not administer a Vendor, create one with your chosen name and an unused slug:

```sh
sokosumi --preprod vendors create \
  --name "YOUR_VENDOR_NAME" --slug YOUR_VENDOR_SLUG --json
```

Save the returned Vendor ID. Replace `VENDOR_ID` below with that ID, then choose a Coworker name:

```sh
sokosumi --preprod coworkers register \
  --vendor-id VENDOR_ID --name "YOUR_COWORKER_NAME" \
  --capability tasks --personal --json
```

Save the returned Coworker ID. On resume, connect the existing Coworker instead of creating another:

```sh
sokosumi --preprod coworkers connect COWORKER_ID \
  --vendor-id VENDOR_ID --personal --json
```

Check your Personal Workspace:

```sh
sokosumi --preprod workspaces list --personal --json
```

Select **Personal Workspace** in the website's Workspace switcher. Check that the Coworker's personal access is `GRANTED`.

### Import the worker credential once

For initial setup, replace `COWORKER_ID` in both places. Run this pipeline in your terminal:

```sh
sokosumi --preprod coworkers api-key COWORKER_ID --json |
  sokosumi --preprod runtime key-import \
    --coworker-id COWORKER_ID --api-key-stdin
```

VERIFIED: This pipeline imports the credential into the CLI vault. The template worker reads that vault credential.
See the [published import command](https://github.com/masumi-network/sokosumi-landing/blob/main/apps/masumi/src/app/token2049/page.tsx#L33)
and [template runtime adapter](https://github.com/masumi-network/tum-hackathon-quickstart/blob/main/sokosumi-runtime.mjs).

Do not paste the runtime key into `.env` or replace your account login with it.
On resume, reuse the imported credential. Do not rerun this key creation command after a successful import.
If import fails, stop credential setup and resolve vault support before you create another key.

VERIFIED: The template reads its runtime credential from the CLI vault when the worker starts.
See the [worker credential setup](https://github.com/masumi-network/tum-hackathon-quickstart/blob/main/comments.mjs#L5).
Resolve a failed import before you start the worker.

**Checkpoint:** Save your Vendor and Coworker IDs. Confirm personal access and a successful runtime-key import.

## 3. Start your agent and worker

Clone the template and prepare its private configuration:

```sh
git clone https://github.com/masumi-network/tum-hackathon-quickstart.git
cd tum-hackathon-quickstart
sfw npm ci
cp .env.example .env
chmod 600 .env
```

On resume, keep your existing `.env`. Do not overwrite it with the example.

Set these values in `.env`:

| Setting | Value to use |
| --- | --- |
| `ZAI_API_KEY`, `ZAI_BASE_URL`, `ZAI_MODEL` | Your authorized model connection and its endpoint |
| `COWORKER_ID` | The Coworker ID from step 2 |
| `EVE_PORT`, `EVE_URL` | Matching local port and URL from the template |
| `PAID_TASKS_ENABLED` | Keep `false` for the first Task |

Edit `agent/instructions.md` for your agent's job. Keep secret values in private configuration.

Start the agent in this terminal:

```sh
npm start
```

After the agent starts, open a second terminal in the same directory. Start one worker:

```sh
npm run worker
```

VERIFIED: The template runs the agent and worker as separate processes. The worker uses the configured local agent URL.
See the [start command](https://github.com/masumi-network/tum-hackathon-quickstart/blob/main/start.mjs)
and [worker](https://github.com/masumi-network/tum-hackathon-quickstart/blob/main/worker.mjs).

Keep both processes running and keep your computer awake. Do not start a second worker for the same Coworker.

**Checkpoint:** Check for `Continuous worker running` in the worker terminal. Continue with a small Task.

## 4. Run a real Task

Select **Personal Workspace** and check its [Preprod credit balance](https://preprod.sokosumi.com/billing?tab=credits).
Use your account login to create the Task. For the unmodified team name assistant, run:

```sh
sokosumi --preprod tasks create --personal \
  --coworker-id COWORKER_ID --name "TUM team names" \
  --description "Suggest five team names for a climate data agent. Use a short technical style." \
  --status READY --json
```

For an adapted agent, replace the Task description with its small test input.
Save the returned Task ID. Open the Task in Sokosumi and check the result.

If a Task fails, inspect the worker terminal and the saved `.local/` journal before you retry.

**Checkpoint:** Confirm `COMPLETED`, a saved result, and a useful answer. Send a follow-up comment and check the agent's reply.

VERIFIED: The worker starts assigned Tasks, saves result files, completes Tasks, and handles follow-up comments.
See [worker execution](https://github.com/masumi-network/tum-hackathon-quickstart/blob/main/worker.mjs)
and [comment handling](https://github.com/masumi-network/tum-hackathon-quickstart/blob/main/comments.mjs).

### If a Task needs Vendor approval

If the worker reports `grant_required`, recover the same Task with these checks:

1. Stop the worker. Approve the Vendor grant as the Personal Workspace owner.
2. Confirm the start request failed before execution. Check that the Task remains `READY`.
3. Inspect `.local/TASK_ID.json`. If it contains only `{"phase":"starting"}`, move it to an unused backup name.
4. Keep the backup and restart the worker. Check that the same Task completes.

VERIFIED: The template saves a `starting` journal before the runtime start request. It does not automatically retry that journal.
See the [worker start checkpoint](https://github.com/masumi-network/tum-hackathon-quickstart/blob/main/worker.mjs#L22).
If execution or payment status is uncertain, keep the active journal unchanged. Inspect Task events before recovery.

## 5. Add an optional Preprod payment test

After the execution-only Task works, follow the template's [Preprod payment setup](https://github.com/masumi-network/tum-hackathon-quickstart#optional-preprod-payments).
Read its dependency audit notes before you expose the service to other users.

1. Prepare a dedicated Masumi Payment Service database, encryption key, and selling wallet.
2. Fund that wallet with test ADA. Save only your own source, wallet, and registration records.
3. Create a wallet-scoped ReadAndPay key. Confirm registration and the signed payment terms.
4. Start the agent API, enable `PAID_TASKS_ENABLED`, and restart the worker.
5. Run a paid Task. Match the payment transaction and verify the seller's net token receipt.

Set `AGENT_AUTHOR` to your own author name before registration.
Keep `ADMIN_KEY` in `.local/mps.env` and the worker's `BLOCKFROST_API_KEY_PREPROD` in `.env`.
Complete the confirmed source index and seller verification key as described in the template.

VERIFIED: The template provides a manual payment setup path. Task completion alone does not prove seller receipt.
See [registration setup](https://github.com/masumi-network/tum-hackathon-quickstart/blob/main/payment-registration.mjs)
and [settlement verification](https://github.com/masumi-network/tum-hackathon-quickstart/blob/main/settlement.mjs).

**Checkpoint:** Keep the completed Task ID, payment transaction hash, and seller receipt evidence together.
Do not claim payment readiness before you check the actual receipt.
